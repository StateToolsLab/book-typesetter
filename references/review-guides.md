# 頁を見てもらうときのガイド線

ユーザーに組んだ頁を見てもらい、直す場所を言ってもらうときの見せ方です。

## なぜ要るか
- 「何行目」「何字目」は、目で数えにくい。スマホで見ているときは、なおさら数えにくい。
- 場所があいまいだと、直す所を取り違える。音声入力では「4 行目」が「14 行目」になることもある。

## 重ねるもの
頁の画像（組んだ PDF を画像にしたもの）の上に、次のものを重ねる。画像そのものは変えず、上に重ねて、出し入れできるようにする。

| もの | 縦組の例 | 横組の例 |
|---|---|---|
| 5 行ごとの線 | 右から 5 行・10 行・15 行の行の間に、縦の線（赤）。上に行の番号 | 上から 5 行ごとに、横の線 |
| 5 字ごとの線 | 天から 5 字・10 字…の所に、横の線（青）。脇に字の番号 | 行の頭から 5 字ごとに、縦の線 |
| 行ごとの字数 | 各行の上に、その行の字数を小さく | 各行の脇に |

- 線の位置は、組んだ版の字の位置を測った値から決める（1 行目の字の位置、行送り、字の大きさ、天）。目で合わせない。
- 字数は、組んだ版の文字の層から数える。縦中横は 1 字と数える。字間を詰めた段落は字数が増えるので、詰めた所の見分けにもなる。字間を変えた行では、字の線と字が少しずれることを書き添える。
- 場所は「33 頁、5〜10 行の間の 8 行目、20〜25 字あたり」のように言ってもらう。
- **線は、位置を合わせる物差しにもなる。** 見出しや章題の位置を決めるときも、「右から 11 行目に置く」「『〈』の頭を天から 10 字の線にそろえる」のように、線を頼りに決めてもらえる（2026-11-10、章扉の位置をユーザーが線で決めた）。決まった位置は、行と字の数で決めごとに書く。
- **のどや見開きに関わる位置は、見開きで見る。** 1 頁だけ見ると、見開きの左の頁でのど（綴じ側）に寄りすぎていることに気づきにくい（2026-11-10、章扉が見開きの左でのどに近くなるため、ユーザーが位置を動かした）。

## 見る頁を作る道具（`tools/viewer/`）
組んだ版の PDF から、ガイド線つきの見る頁（1 枚の HTML と頁の画像）を作る。頁を上から順に並べ、線は出し入れできる。「見開きで見る」で、偶数頁とその次の頁を 2 頁ずつ並べられる。スマホで指で広げて見られる。

1. 本のフォルダに `版面.json` を置く（雛形は `tools/viewer/page-grid.example.json`）。1 行目の字の左端、行送り、字の大きさ、天、行数、字数、最初のノンブル、綴じ（右開きは「右」で偶数頁が右、左開きは「左」）を、組んだ版の文字の層を測って書く。値を道具やページに直に書かない。
2. 版を出すたびに回す:
   ```
   python3 -I tools/viewer/update_viewer.py 版.pdf 版面.json 見る頁のフォルダ "本の題　章"
   ```
   頁の画像（`p/p-01.jpg`…）、スマホ用の軽い PDF（`light_pdf.py`）、行ごとの字数、`viewer.html`、`files.json`（頁と一緒に出す画像の一覧）ができる。
3. **同じ場所に出し直す。** ユーザーがいつも同じリンクで最新の版を見られるようにする。Claude の Artifact なら、同じ URL に、同じ file_path・root と、`files.json` の画像の一覧で出し直す。別の会話から初めて出し直すときは、先にその Artifact を読む。
4. **出す前に、線が字に重なっているかを確かめる。** 線は字の間と行の間に乗り、灰色の字数は各行の上に来るはず。
   - 確かめ方: 手元で見る頁を開いて画像にし、その画像を見る。開けるブラウザが無ければ、ヘッドレスのブラウザで画像にする（例: `chrome --headless=new --allow-file-access-from-files --screenshot=見る頁.png file://…/viewer.html`）。数字でも、頁の画像のインクの端と `版面.json` の値を比べられる。
   - ずれていたら `版面.json` の値を測り直す。組みの道具によっては、文字の層の箱が字からずれている（例: Chrome の PDF では約 10pt 上）。そのときは字の位置を画像のインクで測る。
   - 確かめられなかったら、出すときに「線の位置は未確認」と伝える。確かめたと言わない（2026-11-10、画像が読めないまま出した版があった）。
5. 何を変えた版かは、題の下の一行（`--note`）か、版ごとの一覧に書く。

- いまは縦組だけ。版面の外の柱やノンブルを数えないよう、字数は天から地までの範囲だけで数える（`版面.json` の `数える範囲_pt` で変えられる）。
- 要るもの: poppler（`pdftoppm`、`pdftotext`、`pdfinfo`）。

## 見た目の違う写しでは決めない
- 行の切れ目を動かしてもらうために、Word などに 1 行ずつ写した下書きを作ることがある。書体、字の大きさ、見出しや図の位置が本と違うので、ユーザーは見た目で判断できない。
- 判断は、本と同じ見た目の頁にガイド線を重ねたもので行い、直す場所は言葉でもらう。

## 由来
- 2026-11-10、縦組の本の組み直しで、ユーザーの案。見せた後のユーザーの言葉「このガイド線の使用、かなりいいかもよ」。
- 同じ日に、1 行ずつ写した Word を出したが、ユーザーは「見た目の違いこそ大事なので」と、本と同じ見た目の頁を見て言葉で指示するやり方を選んだ。
- 2026-11-10〜25、同じ本で、版を出すたびに同じリンクの見る頁を差し替えて、ユーザーが 1 頁ずつ確かめた（組み直し 32 まで）。ユーザー「ガイドをみながら指示を出しながら校正できるのいいね」「このビューアーめちゃ便利だったんだよ」。その道具を、本の値を外に出して `tools/viewer/` に入れた。
