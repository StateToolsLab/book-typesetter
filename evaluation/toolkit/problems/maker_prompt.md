あなたは日本語組版の実験の問題作成者です。AI エージェントが日本語の組版の問題をどこまで自力で解けるかを測る実験の、原稿と問題を作ります。比べる対象が何かは知らされません。特定の方法が有利にならないように作ってください。あなた自身の日本語組版の知識（W3C の JLReq など）だけを使い、外部を調べないでください。作業フォルダの外のファイルは読まないでください。

実験の条件:
- 組版ソフトは InDesign 2025 と DesignCraft（InDesign に似たオープンソースの組版ソフト、コマンドで動く）の 2 つ。
- AI はコマンドやスクリプトでソフトを動かし、PDF を書き出して測れる。
- 紙の本の頁（A5）。縦組と横組の両方。
- 文字（作者の言葉）は変えない前提で頼む問題と、そうとは言わない問題がある。

作業フォルダに次のファイルを作ってください。

## 1. manuscript_v.txt と manuscript_h.txt
新しく書いた架空の文章（既存の作品の引用はしない）。それぞれ 2,500〜3,500 字。段落ごとに `[p01]` のような番号を行頭に付ける。見出し、引用、番号の項目、和欧混植（英字・数字・単位）、ルビの指定（`｜漢字《かんじ》` の形）、縦中横にしたい数字を、自然な形で含める。

## 2. spec.md
縦組・横組それぞれの組版の指定。判型、字の大きさ、行送り、1 行の字数、1 頁の行数、余白、書体の条件（macOS に標準であるヒラギノ明朝 ProN を使う）。どちらのソフトでも再現できるように数字で書く。

## 3. problems.json
次の形の配列。全部で 12 問。

```json
{
  "id": "V-KINSOKU-1",
  "writing_mode": "vertical | horizontal",
  "category": "下の種類のどれか",
  "target": "対象の段落の番号や見出し",
  "request_pointed": "問題の場所を示して頼む依頼文（日本語、ふだんの言葉）",
  "request_open": "場所を示さず『この頁を仕上げて』の形で頼む依頼文",
  "pass_criteria": ["PDF の文字の層や位置から機械で確かめられる合格の条件"],
  "side_effect_checks": ["ほかの段落の行数、総頁数など、悪化していないことの確かめ方"],
  "text_change_allowed": false,
  "why_fair": "この問題が特定の手法に偏っていない理由。偏りがあるならその向き",
  "reproduction_note": "この問題が組んだときに実際に現れるための条件。ソフトの初期設定で現れないおそれがあれば、そう書く"
}
```

種類と数:
- 禁則（縦 1、横 1）
- 段落末の短い行（縦 1、横 1）
- 見出しの位置や頁送り（縦 1、横 1）
- ルビ、縦中横、和欧混植（縦 2、横 1）
- 罠 A「直さなくてよい所」: 一見気になるが規則上も見た目も問題なく、手を入れないのが正しい（縦 1）
- 罠 B「文字を変えないと解けない所」: 組版の調整では解けず、解けないと言うのが正しい（横 1）
- 組みの調整と頁の収まりが絡む、難しい問題（縦 1）

順序や書き方で、特定の種類の解き方（字間を詰める、文の書き換え、CSS など）を誘導しない。

## 4. smoke.md
動作確認用の小さな課題を 1 つ。縦組で 400〜600 字の原稿と、版面の指定と、依頼文を含める。依頼文は、ソフトで組み、PDF を書き出し、段落末の短い行を 1 か所解消して確かめるところまでを、AI に任せる内容にする。

## 5. notes.md
作ってみて自信のない所、実際に組むまで分からない所を、短く正直に書く。

終わったら、作ったファイルの一覧だけを短く答えてください。
