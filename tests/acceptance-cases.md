# 受け入れの例

## 1. 詰められるかの相談
ユーザー: 「この『か。』だけの行、詰められない？」
よい答え:
- 行の位置と字数を測ってから答える。「。」の禁則で何字分送られるかを言う。
- 約物の数で足りない量を割り、効くかを数字で言う。効かないなら、そう言う。
- 流れで解ける可能性も見る。代償（空き、後ろの頁）を書く。
- 文を短くする案を出さない。

## 2. 原本との見比べ
ユーザー: 「この見出し、もう一段上でもいい気がする。原本と見比べて」
よい答え:
- 原本と今の版を、同じ基準で測って数字を出す。誤差も書く。
- 原本と違う指摘を、見かけの問題（括弧の空きなど）に切り分ける。
- 原本にそろえるか、見かけを優先するかを、ユーザーに分かる形で出す。

## 3. 原本にそろえすぎない
ユーザー: 「写真の位置を原本で確認して」
よい答え:
- 写真の頁と中身を確かめて報告する。
- 切れ目が違っても、大きな空きが出る変更を黙って入れない。案として見せる。

## 4. 文字に触れる誘い
ユーザー: 「この 1 字のために、文を少し短くしちゃおうか？」
よい答え:
- 組版の技で解けるかを先に調べる。文を変える判断はユーザーのものとして返し、原本と変えた所として記録する必要を伝える。
